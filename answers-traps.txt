1. Which registers contain arguments to functions? For example, which
   register holds 13 in main's call to printf?

   The registers a0-a7 hold function arguments (extra arguments would go on
   the stack). In main's call to printf, register a2 holds 13
   (instruction "li a2,13"), a1 holds 12 (f(8)+1), and a0 holds the
   format-string address.

2. Where is the call to function f in the assembly code for main? Where
   is the call to g? (Hint: the compiler may inline functions.)

   There are no calls to f or g in main: the compiler inlined both. f(8)+1
   is computed at compile time, and main simply loads the constant 12 into
   a1 ("li a1,12"). In the compiled code g(8) was reduced to "addiw a0,a0,3".

3. At what address is the function printf located?

   0x658 (see the jalr in main: "jalr 1576(ra) # 658 <printf>").

4. What value is in the register ra just after the jalr to printf in main?

   0x38 — the address of the instruction after the jalr (li a0,0, the
   start of the exit(0) call sequence), because jalr writes pc+4 to ra.

5. Run the following code:
       unsigned int i = 0x00646c72;
       printf("H%x Wo%s", 57616, &i);
   What is the output?

   "He110 World". 57616 = 0xe110, so %x prints "e110". i's four bytes in
   little-endian memory order are 0x72 0x6c 0x64 0x00, i.e. the characters
   'r', 'l', 'd', '\0', so %s prints "rld".

   If the RISC-V were instead big-endian, what would you set i to in order
   to yield the same output? Would you need to change 57616?

   On a big-endian machine we would set i = 0x726c6400 so that the bytes in
   memory are still 0x72 0x6c 0x64 0x00. 57616 does not need to change:
   %x prints the numeric value of the argument, which is independent of the
   endianness of the machine.

6. In the following code, what is going to be printed after 'y='? (note:
   the answer is not a specific value.) Why does this happen?
       printf("x=%d y=%d", 3);

   An unpredictable (garbage) value will be printed. printf receives 3 in
   a1 for "x", but there is no argument for "y", so printf reads whatever
   value happens to be in register a2 at that moment. The answer is not a
   specific value because it depends on the prior contents of a2.
